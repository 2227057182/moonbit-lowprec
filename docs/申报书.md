# moonbit-lowprec 项目申报书

## 一、项目定位

MoonBit 只有单精度和双精度浮点，没有低精度数值层。本项目提供 binary16、bfloat16、定点与仿射量化四类表示，并读取 GGUF 容器把真实量化权重还原成数值；全部以位模式存储，转换按 IEEE 754 与量化规范定义，验证用穷举而不是抽样。

## 二、为什么需要

2026-11-26 查询 mooncakes.io 全部 3975 个模块描述，`fixed point`、`int16`、`f16`、`fp16`、`bfloat16` 均无匹配。描述零命中不等于代码零实现，对最相关仓库做了源码复检：`matrixlt/moon-onnx` 的 `ml_kernels/quant` 确有 per-tensor 的 int8 与 uint8 仿射量化，按 QuantizeLinear 规范并含银行家舍入；但它没有 float16、bfloat16、逐通道参数、重量化，也不对外暴露类型。其余临近项目覆盖别的范围：`Luna-Flow/floating` 任意精度与区间，`moonbit-community/softfloat` IEEE 浮点软件模拟，`soehi/gguf` 读容器并反量化 ggml 块但不提供类型。

这不是命名差异。binary16 指数 5 位，范围 6.1e-5 到 65504，有效精度 11 位；bfloat16 指数同单精度但有效位只有 8 位；定点没有指数，只有固定标度与两端硬边界，也没有 NaN。三者都不能用 float 代替。

## 三、实现内容

1. F16：位模式存取、字段访问、分类判定；到单精度扩展对全部位模式精确（含次正规数），窄化就近偶数舍入，溢出到无穷，下溢渐进到次正规再归零。
2. BF16：指数 8 位、尾数 7 位。扩展只是左移 16 位；窄化提供就近偶数与截断，截断时若 NaN 载荷落在被丢的低半部会重置 quiet 位，避免变成无穷。
3. Fixed：值为 `raw * 2^-frac`，存在 width 位字段里。五种舍入与两种溢出。舍入在幅值上定义再恢复符号，负数按指定方向走而不退化成向零截断。
4. 量化：仿射与逐通道参数、量化与反量化、31 位乘法因子加右移的重量化（中间不经过浮点）、64 位整数点积。
5. GGUF：解析 v3 容器头，跳过元数据但保留 `general.alignment`，读张量名、维度、ggml 类型与载荷偏移；F32 与 Q4_0 载荷还原成数值，Q4_0 按 32 权重 18 字节逐块展开，权重 j 在低 4 位、j+16 在高 4 位。

## 四、验证

`moon test` 共 43 项，wasm、wasm-gc、js 三后端全通过。穷举部分是全部输入：

- binary16 全部 65536 位模式往返，检查 63490 个非 NaN 值，0 处不符。
- bfloat16 同样全部 65536，检查 65282 个，0 处不符。
- 分类判定与位域在全部 65536 模式上逐一对齐。
- 定点乘法：8 位范围全部 65536 操作数对 × 5 种舍入 = 327680 个结果，对独立 Double 参考。
- 双字宽乘法的原始乘积逐位精确。
- 16 位字段 65536 个原始值，饱和与回绕分别验证。
- 重量化：全部 256 个 int8 码对 Double 比对。
- 舍入界：990 个点覆盖 -0.99 到 0.99，就近偶数不超过半步，截断必须严格更大。
- 信噪比与独立 Double 计算一致；参考向量 60 条由 verify 校验。
- GGUF：324 字节容器的头部字段、两个张量载荷逐字节断言；非容器输入与载荷被截断的容器都必须被拒。

两条实现路径不同：整数移位取整与 Double 取整互证，开发中由此抓到参考实现自身的方向错误。

## 五、可检查性

命令行工具直接读位模式与参数：

```
moon run cmd/main -- f16 0x0002
bits=2 sign=0 exp=0 mant=2 class=subnormal value=1.1920929e-7
```

report 子命令把同一段 256 点正弦放进四种舍入模式：就近偶数 49.65 dB，截断 43.7 到 44.3 dB，最大误差分别是半步与接近一整步。gguf 子命令把一个容器走完整链路：反量化、按张量重新定标到 int8、算 SNR。324 字节样本里 Q4_0 张量仍保持 62.6 dB——粗格式丢掉的精度不会被第二次量化再丢一遍，这正是类型层应当给出的账。

## 六、边界与限制

Int 在本方言中是 32 位有符号数。定点乘法因此限定字段不超过 16 位，乘积低于 2^30；更宽累加走 mul_raw 或 64 位点积；重量化乘积约 2^38，先在 Int64 里形成再取整。限制写在 README 与变更日志。

不覆盖 e4m3 这类非 IEEE 8 位浮点、任意精度、低精度超越函数。
