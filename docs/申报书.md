# moonbit-lowprec 项目申报书

## 一、项目定位

MoonBit 目前只有单精度和双精度浮点，没有低精度数值层。本项目提供 binary16、bfloat16、定点与仿射量化四类表示，全部以位模式存储，转换与运算按 IEEE 754 与量化规范定义，验证用穷举而不是抽样。

## 二、为什么需要

2026-11-26 查询 mooncakes.io 全部 3975 个模块描述，`fixed point`、`int16`、`f16`、`fp16`、`bfloat16` 均无匹配。描述零命中不等于代码零实现，所以对最相关的一个仓库做了源码复检：`matrixlt/moon-onnx` 的 `ml_kernels/quant` 确有 per-tensor 的 int8 与 uint8 仿射量化，按 QuantizeLinear 规范并含银行家舍入；但它没有 float16、bfloat16、逐通道参数、重量化，也不对外暴露类型，是图执行器里的算子。其余临近项目覆盖别的范围：`Luna-Flow/floating` 任意精度与区间，`moonbit-community/softfloat` IEEE 浮点软件模拟，`soehi/gguf` 读 GGUF 容器并反量化 ggml 块。

这不是命名差异。binary16 的指数只有 5 位，表示范围 6.1e-5 到 65504，有效精度 11 位；bfloat16 的指数与单精度相同，但有效位只有 8 位；定点没有指数，只有固定标度和两端的硬边界，也没有 NaN。三者都不能用 float 代替。

## 三、实现内容

1. F16：按 IEEE 754 binary16 做位模式存取、字段访问、分类判定，到单精度的扩展对全部位模式精确（含次正规数），窄化采用就近偶数舍入，溢出到无穷，下溢渐进到次正规再归零。
2. BF16：指数 8 位、尾数 7 位。扩展到单精度只是左移 16 位，不丢任何值；窄化提供就近偶数与截断两种模式。截断时若 NaN 载荷落在被丢弃的低半部，会重新置 quiet 位，避免变成无穷。
3. Fixed：值等于 `raw * 2^-frac`，放在 width 位字段里，底层用 Int。提供五种舍入模式与两种溢出模式（饱和、回绕）。舍入在幅值上定义再恢复符号，所以负数按指定方向走，不会退化成向零截断。
4. 量化：仿射参数与逐通道参数、量化与反量化、用 31 位乘法因子加右移实现的重量化（中间不经过浮点）、64 位整数点积，以及 GGML Q4_0 块的 32 个权重反量化（16 字节打包码加一个 binary16 标度）。

## 四、验证

`moon test` 共 37 项，在 wasm、wasm-gc、js 三个后端全部通过。

穷举部分是全部输入，不是抽样：

- binary16 全部 65536 个位模式往返，检查 63490 个非 NaN 值，0 处不符。
- bfloat16 全部 65536 个位模式往返，检查 65282 个非 NaN 值，0 处不符。
- 两种浮点的分类判定与位域在全部 65536 个模式上逐一对齐。
- 定点乘法：有符号 8 位范围的全部 65536 个操作数对 × 5 种舍入 = 327680 个结果，逐个与独立的 Double 参考比对。
- 双字宽乘法：同样 65536 对，要求原始乘积逐位精确。
- 16 位字段全部 65536 个原始值各加 1，饱和与回绕两种模式分别验证。
- 重量化：全部 256 个 int8 码与 Double 计算比对，精确匹配数作为断言。
- 舍入界：990 个信号点覆盖 -0.99 到 0.99，就近偶数的最大误差不超过半步；同一批点上截断的最大误差必须严格更大。
- 信噪比：报告值与独立的 Double 计算一致，误差为零时返回正无穷而不是哨兵值。

两条实现路径不同：整数幅值移位取整与 Double 取整互相印证，开发中由此抓到参考实现自身的方向错误。

## 五、可检查性

项目带一个命令行工具，直接读位模式与参数，不经过内部状态：

```
$ moon run cmd/main --target wasm -- f16 0x0002
bits=2 sign=0 exp=0 mant=2 class=subnormal value=1.1920929e-7
```

重量化命令会打印推导出的整数乘子与右移量，算术过程可被外部核对。report 子命令把同一段 256 点正弦放到四种舍入模式下比较：就近偶数 49.65 dB，三种截断 43.7 到 44.3 dB，最大误差分别是半步与接近一整步。

## 六、边界与限制

Int 在本方言中是 32 位有符号数。因此定点乘法限定字段不超过 16 位，乘积低于 2^30；更宽的累加走 mul_raw 或 64 位点积；重量化的乘积约 2^38，先在 Int64 里形成再取整。这两条限制写在 README 和变更日志里，不做隐藏。

不覆盖 e4m3 这类非 IEEE 8 位浮点、任意精度、低精度超越函数。
